# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Hermes Agent Self-Evolution uses GEPA (Genetic Evolutionary Pareto Algorithm) to evolve agent skills, prompts, and tool descriptions through reflective evolutionary search. The core loop: wrap a skill as a DSPy module → evaluate on test cases via agent inference → GEPA reads execution trajectories and proposes targeted text mutations → constraint gates → best variant survives.

The project is currently in Phase 1 (skill evolution), with Phases 2-5 (tools, prompts, code, continuous loop) planned but not built.

## Commands

**Note:** This environment requires proxy to be disabled for `uv` and `pip` commands:
```bash
unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy
```

```bash
# Install (uv manages venv + dependencies)
uv sync

# Run tests
uv run pytest

# Run skill evolution (main entry point)
uv run python -m evolution.skills.evolve_skill --skill <name> --iterations 10

# Run prompt evolution
uv run python -m evolution.prompts.evolve_prompt --prompt edp_agent/AgentRule.md --inference edp-agent --iterations 10

# Full agent inference + LLM judge
uv run python -m evolution.skills.evolve_skill --skill <name> \
    --inference hermes-agent --evaluator llm-judge --iterations 10

# Dry run (validate setup only, no API calls)
uv run python -m evolution.skills.evolve_skill --skill <name> --dry-run
```

## Architecture

### Inference backends (pluggable, selected via `--inference` flag)

All backends extend `BaseAgent` and implement `run(system_prompt, task_input, config) -> {"output": str, "messages": list[dict], "completed": bool}`.

| Mode | Class | What it does |
|------|-------|-------------|
| `single-turn` | `SingleTurnAgent` (`evolution/agents/single_turn.py`) | dspy.ChainOfThought direct LLM call — fastest, no tool use |
| `hermes-agent` | `HermesAgent` (`evolution/agents/hermes_agent.py`) | Imports `AIAgent` from hermes-agent repo, calls `run_conversation()` |
| `edp-agent` | `EDPAgent` (`evolution/agents/edp_agent.py`) | Calls EDPAgent's `agent_stream()` with lazy init + session cleanup |

The backend is selected in `EvolutionAdapter.__init__()` (`evolution/core/fitness.py:219`), which instantiates the matching `BaseAgent` subclass.

### Artifact text flow

```
SKILL.md (or AgentRule.md) on disk
  → load_artifact() parses frontmatter + body (core/artifact.py)
  → body becomes the candidate text that GEPA optimizes
  → agent.run(system_prompt=body, task_input) executes inference
  → LLMJudge or keyword-overlap scores the output
  → GEPA uses score + feedback to mutate the body
  → reassemble_artifact(frontmatter, evolved_body) writes the result
```

### Eval dataset pipeline

Datasets are generated by `SyntheticDatasetBuilder` — an LLM reads the skill and produces `(task_input, expected_behavior, difficulty, category)` examples. Split: 50% train / 25% val / 25% holdout. Supports golden datasets and SessionDB mining as alternatives.

### Constraints (hard gates)

Every evolved variant must pass: size limit (15KB default), growth limit (20% over baseline), non-empty, and valid YAML frontmatter with name + description. Failed = rejected regardless of score.

## edp_agent/ directory

Copied from `agent-framework/agent-store/community/EDPAgent/`. This is EDPAgent — an openjiuwen-based ReActAgent with 6-rule AgentRule.md config, 3 Rails, HITL interrupts, and 17 SSE event types.

Key entry points: `initialize_dpa()` (async, one-time setup with Redis/Runner/Rails/tools) and `agent_stream(query, conv_id)` (async generator yielding AgentEvent).

The spec `docs/specs/edp-agent-backend.md` defines the planned integration — a minimal `reload_agent_rule(new_body)` function will be added to dynamically swap the markdown body without reinitializing infrastructure.
